# maestro-ticket

The maestro ticket store and its CLI. Harness sessions call it to create, claim, move and comment on tickets; the Chief of Staff reads its event log to decide when to wake up. `Backlog.md` is a generated view of it.

Go, single static binary, no cgo (pure-Go SQLite driver).

## Build, test, install

From `tools/maestro-ticket/`:

```sh
go build -o bin/maestro-ticket ./cmd/maestro-ticket   # build
go test ./...                                         # unit, race and multi-process tests
go test -race ./...                                   # same, with the race detector
gofmt -l . && go vet ./...                            # lint
go install ./cmd/maestro-ticket                       # put maestro-ticket on $GOBIN
```

`go test -short ./...` skips the test that spawns 200 processes.

## Where the data lives

`--store PATH`, else `$MAESTRO_TICKET_STORE`, else `$(git rev-parse --git-common-dir)/maestro/tickets.db`. The git common dir is shared by every worktree of a repo and is never committed, so all sessions on all `maestro/` branches see one store and the working tree stays clean.

`maestro-ticket render` writes `<repo>/.maestro/Backlog.md` (or `--out`): temp file, fsync, rename, with `<!-- generated by maestro-ticket render, do not edit -->` on line 1. The output depends only on the store, so re-rendering an unchanged store is a no-op diff.

## Guarantees

- **One writer at a time.** SQLite in WAL mode, `busy_timeout=5000`, `synchronous=NORMAL`, `foreign_keys=ON`. Every write is one `BEGIN IMMEDIATE` transaction: the change and its event commit together or not at all. Readers never block writers.
- **Leases, not locks.** `claim` gives `<bot-id>/<session-id>` a lease for `--ttl` (default 30m, 5s to 24h). One bot can run several sessions, each with its own leases. `heartbeat` extends a live lease; a lease that has expired is lost, and the ticket is claimable again, so a crashed session frees its work without cleanup. `release` is safe to repeat. A claim does not change status.
- **Optimistic versions.** `claim`, `release` and `transition` bump `version`; `heartbeat` and `comment` don't. `transition --from S --expect-version N` fails with exit 4 if someone else got there first. A ticket under someone else's live lease can't be moved. Moving to `done` or `cancelled` clears the lease.
- **Idempotent retries.** `--idempotency-key K` on `create`, `claim`, `release`, `transition`, `comment`: a retry with the same key and request returns the first result and writes nothing; the same key with a different request fails with exit 4. Failed writes don't use up the key.
- **Append-only events.** Every write appends to `events` (triggers reject update and delete). `seq` only grows, and events commit in seq order, so `events --since N` with the `next_seq` from the last call never misses or repeats one. No new events means nothing changed.

Statuses and allowed moves live in `ticket/ticket.go` (`transitions`). The normal path is `todo → in_progress → in_review → in_qa → ready_to_release → done`. `in_progress → done` closes work with nothing to review or release. The review and QA gates for code are enforced by role playbooks and permissions, not by the store.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | ok |
| 1 | internal error, or `doctor` found a problem |
| 2 | usage or invalid request, including a disallowed transition |
| 3 | not found |
| 4 | conflict: version, `--from`, claimed by another holder, lease lost, idempotency key reuse |
| 5 | `claim --next` found no work |

With `--json`, errors print `{"error":{"code":"...","message":"..."}}` on stdout.

## Layout

| Path | What |
|---|---|
| `ticket/` | Domain: types, workflow, validation, errors, and the `Store` interface. No storage code. |
| `sqlitestore/` | The SQLite driver. |
| `render/` | `Backlog.md` generation and atomic writes. |
| `cli/` | Flag parsing and output. Talks only to `ticket.Store`, except for opening the store. |
| `cmd/maestro-ticket/` | `main`. |

## Adding a driver

Implement `ticket.Store` (for example on Postgres: `SELECT ... FOR UPDATE SKIP LOCKED` for `ClaimNext`; serialize event inserts, or assign `seq` at commit, so events become visible in seq order). Run the `sqlitestore` tests against it, then select it in `cli.(*call).open`. Nothing else in the CLI changes.
