# 0732 Harness sessions never write tickets; they draft writes as reply fields

- **Context:** 0700 D1 has the engine add `--holder` and `--token` to every ticket write. The old `maestro-write-tickets`, `maestro-groom-board`, `maestro-propose-change`, `maestro-write-report`, `maestro-handoff-note` and `maestro-escalate` all wrote tickets from the session.
- **Choice:** `playbooks/rules.md` says sessions read tickets (`get`, `list`, `events`) and never write one. `tickets.md` replies `tickets` (ref, title, type, kind, role, owner, priority, deps, areas, playbook, status, body) and `fixes` (id, version, op `transition`, `comment` or `update`, and that op's flags); `groom.md` replies the same `fixes`. Deps name existing ids or the `ref` of a ticket earlier in the same list, so the engine creates them in order and maps refs to ids. `propose.md` (proposal) replies the title, the `Report:` body and the escalation line. `investigate.md` replies the fields the engine's `Report:` note needs. The only files sessions still write outside a worktree are the scratch file, evidence, the inbox deletes in curation, and the `adopted` log line in tuning.
- **Alternatives:** Let the session run `maestro-ticket` with a token the engine passes in (the token in a prompt, and writes the engine can't key or retry).
- **Why:** Every write gets the lease token, an idempotency key from the run, and a version check, in one place.
