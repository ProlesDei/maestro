# 0736 A wrong mode or a missing required input fails render, not the session

- **Context:** A template with modes fell through to its default text for any mode it didn't know. `curate` rendered no instructions at all. The others told the session it had `failed`, after the tokens were spent. Lint passed in every case. When QA's step set no mode, `verify` told the QA session that rows QA proves are `later`, so a QA run could pass a ticket it never checked.
- **Choice:** An unknown mode runs `{{template "unknown-mode"}}`, which isn't defined, so `render` and `maestro-play lint` fail on that step, naming it. A required `with:` key that a step doesn't declare fails the same way: `answers` for the answers modes of `draft-setup` (`needs-with-answers`), `answer` for `tickets` escalation (`needs-with-answer`), and `class` for `propose` (`needs-with-class`), which is the bot's tuning, prompt, playbook, persona or drop choice. A session can't see that choice, and without it a dropped change could still be adopted. A declared key that renders empty means "nothing given" (the user confirmed with no changes). `verify` uses its QA text for a ticket at `in_qa` when the mode is empty, because a wrong mode there would pass silently, and in QA a row it couldn't check means blocked.
- **Alternatives:** A field read like `.step.with.answers` (lint checks fields in every branch, so it fails the playbooks that use another mode); a `fail` template function (slice 1's file); keep the "failed" text (costs a session, and lint can't see it).
- **Why:** A typo in a mode or missing wiring shows up in `go test` before any tokens are spent, and the one silent false pass is closed by reading ticket data.
