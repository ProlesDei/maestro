# 0402 Two rules files: one for bots, one for harness sessions

- **Context:** G4.7: personas pointed to rules "in `AGENTS.md`", the user's file, which Maestro must never edit or rely on. G4.8: rules were copied across files (secrets in 8 places, the Junior's 2 tries in 5). The brief asks to split bot rules from harness rules. `docs/design/team-rules-draft.md` is missing (G0.1), so the rules were written from the brief.
- **Choice:** `bot-profiles/team-rules.md` holds the rules every bot follows: bots prompt and harnesses work, Goal → Workstream → Ticket, ship and scout tickets, statuses, tries, the escalation chain, trust levels, preflight, the kill switch, memory tiers, approval by risk and secrets. Bot setup appends it to every persona. `skills/harness/rules.md` holds what every harness session follows; it installs as `.maestro/rules.md` and goes in through the launch flags, so it outranks the user's `AGENTS.md` without touching it. Personas, skills and playbooks link to a rule and never restate it. When a bot and a session must both obey something (secrets, heartbeats), each file states only its own side, once.
- **Alternatives:** One rules file for both (bots would pay to read session rules every turn, and sessions would get bot rules); put the bot rules in a bot skill (skills load on demand, rules must always be loaded); `bot-profiles/_shared/` (folders starting with `_` are skipped by readers).
- **Why:** Each reader loads exactly the rules that bind it, and each rule has one home.
