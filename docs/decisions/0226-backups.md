# 0226 Backups: VACUUM INTO snapshots, rotated, plus a JSON export

- **Context:** The brief asks for an export and snapshot command, run on a schedule, since the store is local-only. Nothing existed.
- **Choice:** `backup` writes `tickets-<UTC time to the ms>.db` into `backups/` next to the store (or `--dir`) with `VACUUM INTO` through a reader connection, so writers keep going. It opens the result and checks `quick_check` and the schema version before reporting success, refuses to overwrite a file, and then deletes all but the newest `--keep` snapshots (default 24, 0 keeps all; it only touches `tickets-*.db`). `backup --every 1h` repeats until stopped (minimum 1m). `export` prints the whole store (tickets with comments, events, schema version, last seq) as one JSON document, read in one snapshot. A snapshot is a working store: point `--store` at it. Restoring is manual: stop writers, copy a snapshot over `tickets.db` and delete `tickets.db-wal` and `-shm`.
- **Alternatives:** Copy the file (unsafe while the WAL holds commits); SQLite's online backup API (not exposed by the driver through `database/sql`); a cron entry (Maestro mustn't edit the user's crontab; `--every` runs under whatever supervises the reaper).
- **Why:** `VACUUM INTO` is a consistent, compact, single-file snapshot in one statement. Checking it before pruning means a bad snapshot never replaces a good one. Who runs it on a schedule: 0239.
