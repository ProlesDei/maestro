# 0228 Area locks: path prefixes, held by live claims

- **Context:** The brief: tickets declare the code areas they touch, and ClaimNext never runs overlapping tickets at the same time.
- **Choice:** Schema v4 adds `areas (ticket_id, area)`. An area is a repo-relative path (`tools/maestro-ticket`, `skills`), trailing slash trimmed, no `..`; `create --areas a,b` and `update <id> --areas a,b` set them (`--areas ""` clears). Two areas overlap when equal or one is a directory of the other (`tools/maestro-ticket` covers `tools/maestro-ticket/cli`, not `tools/maestro-ticketing`). An area is busy while its ticket has a live claim and isn't in backlog. `claim --next` skips tickets with a busy area and takes the next one in priority order; claiming by id fails with exit 4 `area_busy`, except backlog grooming or renewing your own lease. A ticket with no areas never conflicts. The check runs inside the claim's `BEGIN IMMEDIATE` transaction, so concurrent claimers can't both pass it.
- **Alternatives:** Globs (harder to compare for overlap, and nobody needs them yet); hold the area for the ticket's whole active life, in review and QA too, even unclaimed (stricter, but one stalled review would freeze a directory); treat no areas as "everything" (one careless ticket would serialize the board).
- **Why:** Prefix overlap is what a merge conflict looks like at directory level. Tying the lock to the live claim means a dead session frees its areas when its lease is reaped.
