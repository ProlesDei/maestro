# 0881 What the installer's review fixed

- **Context:** Review of `scripts/install.sh` (0880) found it left the 40 copied skill folders visible to `git status`, though 0143 and the footprint hide them through `.git/info/exclude`, so a session's `git add` could commit them. A copy that failed midway (a file named `.agents`, a full disk) left a half install that every rerun then refused. A subdirectory of a repo passed the git check, though harnesses read skills and the exclude lines match paths from the repo's top. Appending to an exclude file with no final newline joined the user's last pattern to ours. `doctor` ran last, so a repo the store refuses (a submodule, a network filesystem) got the files and then a failure, with doctor's report thrown away. The red team then found that an exported `GIT_DIR` let a non-repo through and sent the exclude lines to another repo, that rolling back a new `.claude/` with `rm -rf` would delete a file a harness wrote there during the run, that a symlinked `.claude` put the copies outside the repo where exclude can't hide them, that a read-only skill subfolder made the copy impossible to remove, and that git before 2.31 failed only after copying. The eval for `setup-project` still expected a blank `project-setup.md` template and a manifest, and the script makes neither.
- **Choice:** The target must be the top of a git work tree. Skill names must be lowercase-hyphen folders with a `SKILL.md`, since they become paths and exclude lines. `maestro-ticket doctor` runs before any write and prints its report. Each skill folder is made with a plain `mkdir`, so it fails rather than copies into a folder that appeared since the check. Git's repo-local variables (`git rev-parse --local-env-vars`) are unset first. `.claude`, `.agents`, their `skills/` and `.maestro` may not be symlinks. Copies are made user-writable. If the run stops early (an error or a signal), the skill folders it made are removed and the folders around them only if empty, so a non-zero exit leaves the work tree as it was apart from files others wrote meanwhile; git before 2.31 is refused before any write; the exclude lines go in last and a leftover one is harmless. Exclude gets `.maestro/local/` and one line per skill folder, each once, after a newline if the file lacks one. The uninstall lines list the skills by name, not `maestro-*`, and say the second one deletes the tickets. The eval's setup says `.maestro/project/` is empty. `scripts/install_test.sh` covers each of these with a path containing a space and a stand-in `maestro-ticket`. Still no manifest, journal, lock, status or uninstall command.
- **Alternatives:** Copy into a staging folder and rename it into place (two renames per harness still leave a half install between them, and the rollback is needed anyway). Exclude `.claude/skills/maestro-*/` with one glob (misses a skill named otherwise and hides the user's own). Run `doctor` last and keep the files when it fails (the repo can't run Maestro without its store).
- **Why:** Each fix keeps a promise 0880 or 0143 already made: refuse rather than overwrite, hide the copies, write nothing on failure. The script grows from about 50 lines to about 120, comments included.
