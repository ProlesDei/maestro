# 0781 Slash commands are skills listed under use.yaml commands

- **Context:** Paul asked for `/maestro-work` and `/maestro-create-ticket` as harness slash commands that run playbooks, plus 9 skills that no prompt step should name (pr-risk, pr-review, sharpen, recall, swarm, unslop, figure-it-out, prune, refactor-code). Harnesses find slash commands in their skill folders (`.claude/skills/`, `.agents/skills/`, 0143). But the installer copies only the skills listed under `prompts`, and this slice may touch only `skills/**` and 0780–0789.
- **Choice:** Add a third `use.yaml` list, `commands`. The installer copies the skills under `prompts` and `commands`; the engine never names a `commands` skill in a prompt. Command skills set `disable-model-invocation: true`, so only the user starts them (0143's manual-only rule). Prompt skills leave it unset, because in Claude Code a skill named in the middle of a headless prompt is loaded by the model. The two workflow commands hold no logic of their own: `/maestro-work` picks the next playbook from the ticket's status and runs `maestro-play run`/`resume`; `/maestro-create-ticket` makes one `maestro-ticket create` call. Documented in `skills/README.md`.
- **Alternatives:** List them under `prompts.all`, which would name them in every step and would have a step start a playbook from inside a playbook. Copy every folder in `skills/` (then you can't keep a skill uninstalled). Commit them to this repo's `.claude/skills/` (outside this slice, and they'd only work here).
- **Why:** One list says what gets installed, and nothing in a playbook depends on it.
- **Merge follow-up:** `maestro-play lint` (slice 1) must accept `commands` and check that each name has a folder, the way it does for `prompts`. The Phase 7 installer copies `commands` too. Until then, copy the folders by hand, as the README says. **Status: needs Paul** (the new key).
