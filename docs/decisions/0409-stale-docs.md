- **Choice:** Both diagrams show the runner, workstream Planners, ship and scout tickets, trust levels and the split wrap-up, and README embeds them byte for byte. `optimizations.md` is dropped: role tuning is role memory (`team-rules.md`) and the tuning tier of approval is budgets, tiers and limits. README's status says what isn't built. `project-setup.md` turns its ticket section into a mirror section (agents work only in `maestro-ticket`) and can only raise the bar. The remaining design diagrams get Maestro names and the current layout; `HANDOFF.md` is left as written.

- **Why:** Docs that bots and installers read must match the rules, and one source per diagram stops drift (0006).
