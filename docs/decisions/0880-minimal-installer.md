# 0880 A minimal installer now; packaging waits

- **Context:** Nothing could be installed. The full Go installer (design 0800: manifest, journal, lock, harness detection, status, uninstall, `install apply`) is built on `p7/int` but not merged, and the playbooks, the footprint and the runner contract it packages still change every week.
- **Choice:** `scripts/install.sh <target-repo>` (about 50 lines of bash) copies every `skills/<name>/` into the target's `.claude/skills/` and `.agents/skills/`, refusing and writing nothing if any of those folders exists; creates `.maestro/project/` and `.maestro/local/`; adds `.maestro/local/` to `.git/info/exclude` once; and creates the ticket store with `maestro-ticket doctor` if it's on PATH, else says how. No manifest, journal, lock, harness detection, status or uninstall: uninstall is the `rm -rf` line in the script's header. `scripts/install_test.sh` is its acceptance test. `chief-of-staff/setup-project` asks the user to run it first and has no install steps. It copies every skill folder, not only those `skills/use.yaml` lists; today that's the same set. The Go installer stays parked, unmerged, at tag `ref/installer-v0` as reference. Rule: no packaging work until the playbooks, the footprint and the runner contract have gone two weeks without a breaking change.
- **Alternatives:** Merge the Go installer (it would pin a footprint that's still moving, and every change would need its manifest and migrations updated); keep copying by hand (no repeatable install, nothing to test).
- **Why:** The founder wants something installable now. A script this small is cheap to change or throw away while the shape settles, and refusing on any existing folder is enough to never overwrite a user's file.
