# 0245 Only work that writes code waits on dependencies and areas

- **Context:** Track B ran the dependency and area checks on every claim except `backlog`, and every live claim outside `backlog` held its areas. So the Chief of Staff couldn't claim a `blocked` ticket to answer its escalation while any live claim held an overlapping area, or ever, while one of its dependencies wasn't `done`. Reproduced with the CLI: `claim T-2` on a blocked ticket exits 4 `area_busy`. Likewise `claim --next --status in_review` reported `no_work` with a ticket waiting in review, and a reviewer's claim kept engineers off the same code. 0228 meant areas to stop two sessions editing the same code at once, and only `todo` and `in_progress` edit code.
- **Choice:** `Status.WritesCode()` is true for `todo` and `in_progress`. Only claims on those statuses wait on dependencies and areas, and only live claims on those hold areas. A held ticket moving into `todo` or `in_progress` without `--release` runs the claim checks first (this generalizes 0243's backlog rule); handoffs and escalations release, so they're unaffected. `update --areas` checks overlap only for a working claim.
- **Alternatives:** Keep the checks on every claim (escalations and reviews stall behind unrelated work); hold areas through review and QA (0228 already rejected it: one stalled review freezes a directory).
- **Why:** The lock protects concurrent edits, and review, QA, release and escalation answers don't edit the ticket's code; a send-back to `in_progress` is claimed again and checked then.
