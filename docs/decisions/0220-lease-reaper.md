# 0220 Lease reaper, and no write clears an expired lease silently

- **Context:** F4 and F12. An expired lease was only logged when someone re-claimed the ticket, with the new claimer as actor. Releasing your own expired lease logged `released`. An unclaimed terminal move cleared an expired lease and logged it as `released` on the transition. An event-driven Chief of Staff never learned a session died.
- **Choice:** `Store.Reap` (CLI `reap [--every D]`) frees every expired lease in transactions of at most 100 tickets. Each one logs `lease_expired` with actor `maestro-ticket` and data `holder`, `token`, `expired_at` and `expiries`, and adds one to the ticket's new `lease_expiries` count. Every write that touches a ticket (claim, release, transition, comment) does the same for that ticket first, in its own transaction, so the log never misses an expiry. Freeing an expired lease doesn't bump `version`, since readers already saw it as expired: an `--expect-version` read before the expiry still matches. The lease token is kept, so the next claim still gets a larger one. A write that fails rolls its expiry back too; the reaper catches it later. Heartbeat doesn't reap (it fails, so nothing commits).
- **Alternatives:** Reap from reads (reads are read-only transactions and must not block writers); bump `version` on expiry (would break `--expect-version` for whoever noticed the lease ran out); reap only from the background process (any write in between would still clear or overwrite the lease unreported).
- **Why:** The reaper reports dead sessions promptly. Logging inside every write keeps the guarantee even when no reaper runs. Run `maestro-ticket reap --every 30s` next to the watcher; 0239 lists who must start it.
