# 0750 What the Planner, Chief of Staff and Ops playbooks add to the 0700 schema

- **Context:** Slice 5 of 0700 turned 16 playbooks into YAML while slice 1 built the engine at the same time. These playbooks branch more, write many tickets, keep cursors and have no ticket at all, which the contract in 0700 A2 doesn't cover.
- **Choice:** The playbooks use these, and `maestro-play` must accept them:
  - **Top level:** `input: required | optional` for request playbooks the user starts, as `run ... --input <text>` → `.input.text`. `claim: false` playbooks run without `--ticket` or `--next`. `session: run` is one session for the run when there's no ticket; leave out `session` when there are no prompt steps. `cursor: {name, save}`: `.cursor` is the stored value (`0` the first time), and `save` is rendered and stored per bot **only at `done`**, so a run that ends early or blocks repeats next time. `done.log` is a template for the log line; `done.to`, `done.role` and `done.actor` (`--actor` for a scout's owner) are templates. `done.to: keep` posts the note and releases.
  - **Intake:** besides `category`, `status`, `kinds`, `unless_latest` and `unless_body`: `type` (`ship` or `scout`), `owner`, `latest` (the latest comment's prefix, through `list --latest-prefix`) and `title` (a title prefix). `--ticket` checks only `status`, so the Chief of Staff can resume a ticket that waits on the user.
  - **Outcome targets:** `done` (go to the `done` wrap-up now) as well as `next`, `block`, `end` and a step id. `end` stops without `done`: no transition and no note, but the engine still releases the claim, logs and cleans up. A step that's only reached by a jump goes after one whose `on:` ends in `done` or `end`.
  - **Step keys:** `reason:` is the `Skipped:` text when `when:` is false. `block: {to: chief-of-staff}` on a step routes that step's block to the Chief of Staff with role `chief-of-staff`; otherwise it goes to the owner. `mode:` is passed to the template as `.mode`. On a `ticket:` step, `body:` is rendered and passed as `--body-file -` when it isn't empty. `each: <dot path>` runs the step once per list item, with `.item` and `.index` (an int), keys `<run>:<step>:<index>` and `.steps.<id>.results` (one record per item, in order). A missing path is an empty list. The outcome is `fail` if any item failed, after trying them all. `when:` is evaluated per item.
  - **Step records:** every step has `outcome`, `skipped`, `exit_code`, `output`, `output_path`, `summary`, `json` (the output parsed when it's JSON; ticket steps always are), `reply`, `choice`, `text` and `results` from the start. Integral JSON numbers in replies decode as ints, so `index` works with them.
  - **Template data and functions:** `.ticket` is `get --json` plus `kind` (the `Type:` body line). `.run.date` is `YYYY-MM-DD`. `.project.main_branch` and `.project.environments` (`name`, `deploy`, `rollback`, `smoke` from "Release") come from `project-setup.md`. Functions are `json`, `quote` (shell-quote one argument; the engine splits a rendered `ticket:` or `run:` line shell-style, with no expansion), `join <list> <sep>`, `latest <ticket> <prefix>` (the newest comment body with that prefix, or `""`), `line <key> <text>` (the value of the first `<key>: ` line, or `""`) and `latestLine <ticket> <key>` (`line` over the comments, newest first).
  - **Lease flags:** the engine adds `--holder` and `--token` only to writes on the claimed `.ticket.id`. Writes to other tickets (creates, grooming fixes, proposals) carry neither, or the store refuses them as `lease_lost`.
  - **Built-in block:** the escalation note ends with `Return-role: <role>`, the role the ticket had when claimed (0436).
- **Alternatives:** One playbook per branch (16 would become about 30); a `shell:` step for loops and parsing (that bypasses the allowlist, 0700 A1); waiting for slice 1's schema first (0700 says no slice waits).
- **Why:** Each addition is the smallest one that lets a playbook branch, loop or write without a judgment call. Everything else the 0700 contract settles. If slice 1 picked other names, renaming them in these 16 files is mechanical.
