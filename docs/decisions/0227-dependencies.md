# 0227 Dependencies: only done unblocks, no cycles

- **Context:** The brief: ClaimNext only returns tickets whose dependencies are done. There was no dependency table, so the Planner used `blocked` for ordering (G5.5).
- **Choice:** Schema v4 adds `deps (ticket_id, depends_on)`. `create --deps T-1,T-2` and `update <id> --add-deps/--remove-deps` set them; every dependency must exist, a ticket can't depend on itself, and an edge that would close a cycle fails with exit 2. Tickets show `depends_on`. `claim --next` skips a ticket while any dependency isn't done. Claiming one by id fails with exit 4 `waiting_on_deps`, except a backlog ticket (grooming) or renewing a lease you already hold. Only `done` counts: a cancelled dependency keeps the ticket waiting until someone removes it, since cancelling the base usually means the dependent needs a rethink. Transitions don't check dependencies; the claim is the gate. `update` logs an `updated` event, is fenced like a transition, and doesn't bump `version`.
- **Alternatives:** Count cancelled as satisfied (silently starts work on a dropped foundation); block the dependent automatically (adds status churn and fights 0200's blocked-returns-to-origin rule); check dependencies on `todo → in_progress` too (unclaimed moves are the Planner's, 0206).
- **Why:** The claim is where work starts, so that's where waiting belongs. Refusing cycles at write time keeps "waiting forever" impossible.
