# 0244 Red-team fixes to track B: area spellings, backup pruning, keepalive TTL and pids

- **Context:** The track B review's red team (ship/wave2) found, beyond 0243: areas such as `./tools/x` or `tools/x/..` were stored as written, so they never overlapped `tools/x` or `tools`; `backup` pruned every `tickets-*.db` in the folder, which deleted a store named `tickets-1.db` and an unrelated archive when `--dir` was the store's own folder; `claim --ttl 0 --keepalive` passed `0s` to the keepalive, which exited at once with a usage error nobody saw while the claim reported success; and `--keepalive 1` (or a pid that answers `EPERM`, another user's or a recycled one) counted as alive forever, so the lease never expired.
- **Choice:** Areas with a `.` or `..` segment are refused (exit 2); areas stay case-sensitive, like git paths. Pruning matches only the full snapshot name (`tickets-YYYYMMDDTHHMMSS.mmmZ.db`) and never the store's own file, compared by file identity so a symlinked path can't hide it. The claim passes the validated TTL (the default for `0`) to the keepalive. A pid is alive only if it is above 1 and (on unix) signalable by us; `claim --keepalive` and `keepalive --pid` refuse anything else with exit 2. Each fix has a test that fails on the old code.
- **Left open (minor):** the set `todo, in_progress` is spelled in `Status.WritesCode` and twice in SQL (0245), so a new working status must change all three. Also: a replayed `claim --keepalive` with the same idempotency key starts a second keepalive for the same lease (both stop on release); a recycled pid of our own user still keeps a lease alive (needs the process start time from `/proc`); `events --since` past the last seq after a manual restore returns nothing (the README's restore steps now say to reset cursors); backfilled outbox payloads print 3 fractional digits where `events --json` trims zeros; doctor's "every event has an outbox row" check will need to allow pruned rows once delivery prunes them.
- **Alternatives:** Clean areas with `path.Clean` instead of refusing them (hides a typo in a plan); fold case (false overlaps on Linux).
- **Why:** Each one breaks a promise track B makes (areas never overlap, pruning only touches its own files, a claim's keepalive runs) with ordinary inputs.
