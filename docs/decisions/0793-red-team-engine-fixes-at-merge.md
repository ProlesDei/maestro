# 0793 The merge's other red-team fixes, and what stays open

- **Context:** Besides the trailer and sha fixes (0792), the red-team pass on `pb/int` found a resumed run taking back a ticket that had moved on, rules that lint checked but the engine didn't, and three gaps in the `commands` lint.
- **Choice:** A resume whose lease lapsed reads the ticket first and is `lost` if its status changed, unless the crash was inside one of the run's own ticket writes. The ticket step and the `done` wrap-up refuse `done` outside 0760's five playbooks. `--actor` is an engine flag and `claim` a reserved step id. Lint scans prompt templates and `bots:` lists for commands, and a heading saying "not in your own session" exempts nothing. `fix-sent-back` takes only tickets whose latest note is a `Handoff:`. The improvement loop's eval tasks must be `<role>/<job>` names. Open, all minor: clean-up kills any PID a reply lists whose command matches (sessions already have `Bash(kill *)`); `each:` has no item cap; `--not-family` excludes only the latest author's family; `run:` steps carry no idempotency key, so the runner must make `merge` and `deploy` safe to repeat; `MAESTRO_RUN_ID` (0791) only stops processes that keep it.
- **Alternatives:** Fix the open items now (each needs a runner or store change that Phase 6 or 7 owns); leave the lint-only rules to lint (an unlinted playbook could break them).
- **Why:** Each fix is small, tested and inside the engine or a playbook; the open ones need code that doesn't exist yet.
