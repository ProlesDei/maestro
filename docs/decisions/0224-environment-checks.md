# 0224 Environment checks before opening the store

- **Context:** F9. The store took any git common dir and any filesystem: a bare repo got `bare.git/maestro/tickets.db` and `doctor` said ok. The brief: refuse or fall back on network filesystems, unreliable container locking, submodules and bare repos.
- **Choice:** Refuse, with exit 2 `invalid` and a message saying what to do. The git default refuses a bare repo and a submodule (its store would split from the superproject's); `--store` or `$MAESTRO_TICKET_STORE` still works there. Every command that opens the store first checks the store's directory (new package `envcheck`): `statfs` refuses NFS, SMB/CIFS, AFS, Coda, NCP, Ceph, Lustre, GPFS, FUSE, 9p and virtiofs; a probe takes an OFD write lock on a temp file and fails if a second open file gets the same lock. `doctor` lists both checks and doesn't open a store that fails them. `MAESTRO_TICKET_ALLOW_UNSAFE_FS=1` turns filesystem and lock failures into passing notes, for setups the checks misjudge. Non-Linux platforms skip both, reported as not checked. A relative `--store` now resolves against the working directory the CLI was given (F13).
- **Alternatives:** Fall back to `journal_mode=DELETE` on shared filesystems (still needs working locks, which is the part that breaks); warn only (silent lost writes are the failure we're preventing); allow FUSE (sshfs and gcsfuse are network filesystems under FUSE, and Docker Desktop shares folders through it).
- **Why:** A store that loses writes is worse than one that won't start. The escape hatch keeps a false positive from blocking anyone.
