# 0760 What evals/check.py keeps, adds and hands to maestro-play lint

- **Context:** 0700 C moves the playbook checks out of `evals/check.py`, because Python here has no YAML parser and the engine owns the schema. It didn't list which old checks go where, or what replaces the skill checks once Maestro ships no skills.
- **Choice:** `check.py` keeps links, backticked repo paths (now in `.yaml` files too), README's diagram embeds, golden-task frontmatter and sections, and coverage, by globbing `playbooks/<role>/<job>.yaml` (roles are folders other than `_*` and `prompts`, each with a bot profile). It adds: any Markdown playbook left in a role folder fails; `skills/` may hold only `README.md`, `use.yaml` and flat `<name>/SKILL.md` folders; and no file under `bot-profiles/` or `playbooks/` may name a `skills/` path other than `skills/`, `skills/README.md` and `skills/use.yaml`, a `maestro-<x>` that isn't a folder in `tools/`, or call a skill in `skills/` as `/name` or `$name`. A skill's name as a plain word is fine, so the user can name a skill `review`. `evals/test_check.py` tests each check on a temp tree. These move to `maestro-play lint` (slice 1): step format and types; runner request names against the Requests table in `docs/runner.md`, and only `get`, `list`, `events`, `doctor`, `create`, `comment` and `transition` as runner ticket requests; only `operations-manager/release`, `operations-manager/infrastructure-request`, `planner/plan-project`, `planner/accept-report` and `chief-of-staff/handle-escalation` may end in `done`; `--type` is `ship` or `scout`, and a scout `create` needs `--owner`; no `--add-try`; `comment` takes no `--expect-version`; every listed skill in `use.yaml` has a folder.
- **Alternatives:** Parse YAML with a hand-written subset parser in Python (a second schema to keep in step with the engine); drop the skill-name check (then nothing stops a playbook depending on a skill again).
- **Why:** Each check lives with the code that owns its format, and the one rule Paul asked for, that nothing depends on a skill name, gets a check that doesn't depend on any skill existing.
