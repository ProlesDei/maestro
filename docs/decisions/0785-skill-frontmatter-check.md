# 0785 check.py checks that each skill's frontmatter parses

- **Context:** In review, `skills/maestro-prune/SKILL.md` had `description: Clean up a repo's dead weight: unused files…`. YAML reads the second `: ` as a nested mapping, so a harness can't parse the block. The skill then loads without `disable-model-invocation`, or doesn't load at all. 0760 checks only the folder layout, and `check.py` has no YAML parser.
- **Choice:** For each `skills/<name>/SKILL.md`, `check.py` also checks that the file has frontmatter and that its `name` is the folder name. It also fails the usual ways a one-line-per-key block breaks: a plain value with `: ` or ` #`, or one that starts with a reserved character (`` ` ``, `@`, `[`, `{`, `*`, `&`, `!`, `%`, `,`, `?`); text after a closing quote; a duplicate key; or an indented line under a key that already has a value. Nested maps and `|` or `>` blocks pass. It reads `disable-model-invocation` the way YAML does, so `True` counts. Anything else in the YAML is the harness's to read. The check still doesn't read skill bodies, so skills may name each other.
- **Alternatives:** Parse the frontmatter in `maestro-play lint` (it parses `use.yaml`, but it lints only listed skills, and it isn't on this branch); leave skills unchecked because they're the user's (a broken flag on a command that deletes files fails silently).
- **Why:** The check is cheap. The failure it catches is silent, and it turns a manual-only command into one the model can start.
