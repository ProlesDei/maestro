# 0745 The slice 4 playbooks follow slice 3's template interface and slice 1's intake

- **Context:** The review of slice 4 linted the 12 playbooks with slice 1's `maestro-play` and rendered them against slice 3's templates. Four playbook choices broke at merge, beyond the 0740 additions slice 1 doesn't have yet. The reviewer and QA filtered intake on their own role, but a ticket keeps its author's role in `in_review` and `in_qa`. Several prompt steps set no mode or a mode the template doesn't have, so the step took the wrong branch: QA's `verify` ran as the engineer's, which marks QA's own rows `later`. Reply fields were named differently from the templates' `reply:` headers (0730). And `vars:` passed values no template reads.
- **Choice:**
  - **Intake:** `review-change` and `verify-ticket` take `role: any, type: ship`, as slice 1's fixture does.
  - **Modes:** each prompt step sets the template mode it means: `plan` `pattern` (Junior) and `bug`; `feedback` `takeover`; `verify` `qa` and `guide`.
  - **Reply fields:** a playbook uses the template's name where it has one: review's `sha` and `findings`, baseline's `baseline`, feedback's `decision`, investigate's `next_tickets`, draft-setup's `draft`. Object lists render with `json` in notes.
  - **No `vars:`:** the 0740 `vars:` row is withdrawn. Steps hand work on through the scratch file (0731), and the verification guide's draft is `{{.run.scratch_dir}}/verify.md`, a path the engine knows, never one a reply names.
  - **QA's commit:** `verify` replies the `sha` it tested, and `pass` requires it to equal review's `sha:`, so a reused `<id>-qa` checkout at another commit can't pass.
  - **Order:** `worktree` comes before `feedback` in the sent-back and takeover playbooks, so `feedback.md` gets the branch.
  - **Review:** the review step's `failed` (head moved, or branch missing) goes on to the `head` gate, which sends the ticket back. A `secret` gate blocks to the Chief of Staff even when the reply says `done`, and a `reviewed` gate blocks a failed review on the handoff's own head.
- **What the merge still needs:**
  - **Slice 1:** the 0740 rows (a list `intake`, `.ticket.trailers`, `int` and `add`, step `session: fresh`, templated `done.to`, `done.role` and `block.to`); `.step.mode` (0730), which slice 1 calls `.mode`; and `.run.scratch_dir`. 0746's trailer rule, with `authorFamily` changed from the first line to the last. `family: not-author` excludes every `author-family:` on the ticket, because take-escalation keeps the junior's commits; the built-in `Escalation:` note adds one.
  - **Slice 3:** reply fields the playbooks read and the headers lack: `review` `secret` (and "a secret or a live hole: blocked"), `plan` `pattern` `example`, `baseline` `trace` `hotspots`, `baseline` `characterise` `gaps` and `broke`. Plus three rules: `baseline` `after` replies failed when the target isn't met beyond the spread; `feedback` `takeover`'s restart reverts on the same branch (0741); `review.md` reads the branch from the handoff's `branch:` line when `.run.branch` is empty, because the reviewer has no worktree, and diffs `main...<sha>`, not the branch.
  - **Slice 2:** `install write --commit` may replace a file it wrote earlier on the same ticket's branch, or the guide's sent-back path always blocks at `install`. A read-only `head <id>` request (0751) would let review compare the head without trusting the reply's `sha`. Sessions get only the read subcommands of `maestro-ticket` (0732); `runner.md`'s `Bash(maestro-ticket *)` lets one post its own `Handoff:` with forged trailers. `worktree add --detach <sha>` resets or refuses a reused checkout at another sha.
  - **Slice 5:** `latestLine` (0750) and `.ticket.trailers` read the same lines. Keep one, with 0746's rule.
- **Alternatives:** Keep slice 4's names and ask slice 3 to rename its templates (seven playbooks in slice 4 and more in slice 5 already read them); pass the draft path through `with:` (no template reads it).
- **Why:** The template is the prompt's interface, so a playbook that names a field or mode it lacks fails silently, with a reply the gate then misreads. Matching it now leaves the merge only the engine rows to add.
