# 0752 The Chief of Staff talks through `ask` steps, and setup carries its own definition-of-done steps

- **Context:** With `talk-to-user` gone (0700 B), the Chief of Staff's playbooks still have to send briefs, digests, recaps and questions. `setup-project` used to run `definition-of-done` "in this session", and `recap` passed each answer to `handle-escalation`. The engine has no step type for either.
- **Choice:**
  - Every message to the user is an `ask` step whose question holds the output to read, the line limits and the rules, with `choices: [sent]` (or `[sent, failed]` where a failed send must repeat). The bot writes the message in its own voice and resumes the run. A real question to the user is the same step: the bot asks and answers with the user's reply as `--text`. No prompt template drafts a message, so the six CoS runs that only report spend no harness tokens.
  - A decision that waits on the user doesn't keep the run or the lease. `handle-escalation` posts `Handoff: waiting on the user:`, releases and ends. The answer starts a new run with `--ticket <id> --input <answer>`, which `recap` does through the runner's `play` request, one per answered decision.
  - `setup-project` inlines the five definition-of-done steps (same `draft-setup` modes and the same floor gate), so `write` puts the file down once. `definition-of-done` stays standalone for later changes, on a `maestro/dod-<date>` branch and pull request.
  - `release` and `housekeeping` have no prompt steps. Every release gate is a comparison on notes, the head sha, `trust` and "Release" (0700 B, `maestro-check-release`), and `housekeep` checks leases and paths itself.
- **Alternatives:** A `message:` step type (a seventh type for something `ask` already does); a `brief` prompt template (tokens for formatting a summary); nesting a run inside a step (pausing two runs at once, with two leases).
- **Why:** Both stay within the six step types. The bot keeps the one job 0700 D1 leaves it, talking to people, and every write stays a deterministic step.
