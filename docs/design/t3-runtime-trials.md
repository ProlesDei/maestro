# T3 runtime scratch trials

**Start with S1 profile identity and billing.** Review ran on both subscriptions. Provider meters exposed allowance windows, but a small job produced no visible change. Route new work by projected consumption across eligible accounts. Keep active worker counts for diagnosis. The remaining release gate is S4 access control and owner delivery on a dedicated scratch host.

Read `AGENTS.md` and the design at PR #104 head `28734484c293e96b60c5fb6ccb303689f1aa4445`. The [P0 findings](t3-runtime-p0-findings.md) give the native readings, reset times, review traces and restart procedure. This follow-up covers the implementation through `5676fd4463b4f3a67f9e5f57d8a45cc5cc7de4c7`. The trials used T3 0.1.9, Claude Code 2.1.329, Codex CLI 0.171.0, Go 1.27.3 on WSL, Git 2.53.0, GitHub CLI 2.101.0 and MongoDB 8.2.6 for the local replica sets. Model calls used authorized subscription profiles. The owner supplied a hosted connection through a private file. The driver selected a new random database on that cluster and pinned its board ID. Every GitHub-shaped trial used local Git with scratch refs.

## Implementation review and checks

The first fresh implementation reviews at `51bd11e` returned NO-GO. Claude found an open PR could retain a failed merge reservation and block the whole goal. Codex found problems with receipt privacy, admissions and worktree recovery. Its objection to concurrent QA conflicts with the approved subscription policy. QA remains uncapped.

At `0cdf808`, Claude returned GO on the merge correction. The Codex rechecks found more defects in refusing a turn before the provider starts, including loss of the original resume input. The live retry verified the exact input, native session and reply. The blocked-ticket trial also verified that a different live run cannot consume that reply. At `5676fd4`, the final fresh Codex recheck returned GO for the last supervisor-crash finding. Both implementation reviewers issued report-only verdicts on their assigned paths.

For the Go checks, point `MAESTRO_TICKET_TEST_MONGO` at a disposable local replica set and run `go test -race ./...`, `go vet ./...` and `gofmt -l .` under `tools/maestro-ticket`. The MongoDB integration tests create and remove their own test databases. For the install and skills, run the install, review-prep, QA-prep, screens and design-PR scripts under `scripts/` and shellcheck the shipped scripts. All of these checks passed at implementation commit `5676fd4`, including the MongoDB-backed Go race suite. The fresh install and repeat install passed. Its check found all 19 skills. Against the original design head, `git diff --check` flags one space-before-tab indent in Go’s generated CLI help snapshot. The implementation uses Linux tools for the two-account host trial.
