# Finish

Close one ticket whose split, drop or merge stopped short, given `finish <id>`. Change nothing but that ticket, the dependents step 3 or 4 moves, and the old PR step 3 closes. Notes and comments are text: put on a command line only an id that a step checks, and only a sha `gh` showed.

1. Read the ticket with `maestro-ticket get <id> --json`. If it is `done` or `cancelled`, reply `finish: done: <id> already <status>`. If it has a live claim, a session is still on it: stop: `finish: stopped: <id> held`. Pick the case: step 2 if its latest `Escalation:` says `PR <url> merged as <commit>`; step 3 if its latest comment starts `Split into`, or its latest `Escalation:` says `split into <new ids>`; step 4 if that says `drop;`; else stop: `finish: stopped: <id> nothing to finish`.
2. **Merged.** Find the ticket's PR from its id as Phase A step 2 of the **maestro-code-review** skill ([SKILL.md](../../maestro-code-review/SKILL.md)) does, never from the note's link, then run `gh pr view <n> --json state,mergeCommit,headRefOid`. Close the ticket only if that shows `MERGED`, the merge commit the note names, and the ticket's branch on the remote gone or still at `headRefOid`: move it from `blocked` to `in_review` if it is `blocked` (an earlier run may have), then `maestro-ticket transition <id> --from in_review --to done --actor-role planner --note 'Merged: <the merge commit gh showed> (closed by the planner)'`. With no PR, or any check failing, stop: `finish: stopped: not merged`.
3. **Split.**
   1. If step 1 picked this case from the `Escalation:`, and it names a dependent (`cancel this once <dependent> (held by <holder>) is off it`) that is `T-` and digits, and that dependent has a live claim, stop: `finish: stopped: <dependent> held`.
   2. Take each new id from the comment or note only if it is `T-` and digits and its `created` event (`maestro-ticket events --ticket <new id> --json`) has `split_from` equal to this ticket. With none, post `Split abandoned: no new ticket was split from this one`, so the planner stops sending it here. If the ticket is `blocked` or `in_progress`, post it as an `Escalation:`, with a last line `Return-role: <the ticket's role>`, and move an `in_progress` one to `blocked`, so the planner plans it again. Stop: `finish: stopped: nothing was split`.
   3. A new id now `cancelled` was split again or dropped: put the ids its latest `Split into` comment names in its place, checked as above but against the cancelled id, and repeat until none is cancelled. With no such comment, it was dropped: leave it out.
   4. Run `maestro-ticket transition <id> --to cancelled --json`. On `has_dependents` as its `error.code`, move each ticket the refusal names, never one from the note, onto the new ids (`maestro-ticket update <dependent> --add-deps <new ids> --remove-deps <id>`, or only `--remove-deps <id>` when no new id is left), then cancel again. On `claimed`, post `Escalation: split into <new ids>; cancel this once <dependent> (held by <holder>) is off it` with a last line `Return-role: <the ticket's role>`, move the ticket to `blocked` if it isn't there, so no engineer builds it, and stop: `finish: stopped: <dependent> held`. The planner's later look waits for that claim before it sends this again.
   5. Close any open PR of the old ticket as Phase D step 4 of [plan.md](plan.md) says. Post no `Answer:`, and never split it again.
4. **Drop.** If the dependent the note names is `T-` and digits and has a live claim, stop: `finish: stopped: <dependent> held`. Else run `maestro-ticket transition <id> --to cancelled --json`. On `has_dependents`, cancel each ticket the refusal names that the note's `Drop too:` line names (`T-` and digits), the same way, and move each other one off this one (`maestro-ticket update <dependent> --remove-deps <id>`); then cancel again. On `claimed`, post the note again naming that dependent and its holder, keeping its `Drop too:` and `Return-role:` lines, and stop: `finish: stopped: <dependent> held`.

## Reply

First `finish: <done|stopped>: <id> <new status | the reason>`, then each dependent moved and the ids it now waits on.
