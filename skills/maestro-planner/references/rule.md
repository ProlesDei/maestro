# Rule

Given `rule <id>: <decision>`, carry out the decision as given, the planner's or the chief of staff's: post it and move the ticket.

1. Read the ticket: its status, the latest `Escalation:`, the latest `Kickback:` and every `Answer:`. If it is `done` or `cancelled`, stop and say so. Edit it under a claim, as the skill says; if someone else holds it, stop: `rule: stopped: <id> held by <holder>`.
2. **Hold or lift.** For `hold, set by <who>: <why>; lifts when <fact>`, the ticket must be `todo`, `backlog`, `in_progress` or `blocked`, else stop: `rule: stopped: can't park <status>`. Move it to `backlog` parked `hold`, except a `blocked` one whose `Blocked-from:` is `in_review`, which stays `blocked`. Comment `Hold: set by <who>, <today's date>: <why>; lifts when <fact>`. A lift moves a parked `backlog` ticket to `todo`, clears its parked reason and comments `Answer: lifted: <why>`. Do only this step, except for a lift on a `blocked` ticket, which goes on like any other ruling.
3. **Post.** If the decision drops an item of a `Kickback: QA fail at <H>` and no `Retest:` came after that `Kickback:`, first post `Retest: planner at <H>: <why>`: only a new QA run clears the item. Then post `Answer: <decision>`; one that changes an earlier `Answer:` names it and says why. For a criterion, the answer reads `Answer: criterion <n> now reads: <text>` (or `is dropped: <why>`), and you edit or strike it in the body. On a `Design:` ticket, `approved:` with a letter other than the latest `Design spec:`'s `Pick:` approves a direction with no criteria yet: post `Answer: changes: make <letter> the pick, with its own criteria`.
4. **Move**, by the first that fits:
   - **Split or rewrite:** follow [plan.md](plan.md) for this id, and reply as it says under a first line `rule: <done|stopped>: <id> <split into <ids> | the reason>`.
   - **Drop:** remove `<id>` from each open dependent's deps, and cancel the same way each dependent the decision drops or a `Drop too:` line on the latest `Escalation:` names. If someone else holds a dependent, post `Escalation: drop; cancel this once <dependent> (held by <holder>) is off it`, then `Drop too: <ids>` for dependents still to cancel and `Blocked-from: <its status before blocked>` last, move the ticket to `blocked` and stop: `rule: stopped: <dependent> held`. Else cancel it, and close its open PR, found by branch `maestro/<id>`, with a comment saying why.
   - **Approved design**, on a `Design:` scout whose `Answer:` opens `approved:`: the latest `Design spec:` is the spec, with each `Taste calls:` default taken. Follow Slice and Create in [plan.md](plan.md) with it in place of the Frame spec. Create only engineer tickets, one per slice of the screens, with each criterion as written in the spec's `Criteria:` and each body naming the PR and `Design: <id>`. Close the draft PR on `maestro/<id>` with a comment giving the direction and the new ids. Move the ticket from `blocked` to `done`: only the planner skips review for a `Design:` scout.
   - **Merged PR:** on a `blocked` ticket whose latest `Escalation:` reads `PR <url> merged as <M>`, or QA's `merge <M>: <reason>`, check the PR on `maestro/<id>` is merged at the head the note names and its remote branch is gone or still at that head; if not, stop and say why. For `merge <M>:`, file the failure on main as an `urgent` ticket with **maestro-create-ticket**. Move the ticket to `done`: its code is on main.
   - **Any other `blocked` ticket:** return it to the status on the latest `Escalation:`'s `Blocked-from:` line (`backlog` keeps its parked reason), or to `in_progress` when the decision sends the work back to the engineer. A note with no `Blocked-from:` comes from an older Maestro: an `Escalation: review at` or `Escalation: QA at` goes back to `in_review`, any other to `in_progress`.

   Then, if the ticket is `in_progress` and the decision drops every item of its latest `Kickback:` still standing, move it to `in_review`.

## Reply

First `rule: <done|stopped>: <id> <new status | the reason>`, then each comment posted and each dependent moved; when the owner said yes to a review escalation at `H`, `Next: maestro-code-review <id> --approved <H>`; for an approved design, each screen ticket in the shape [plan.md](plan.md#reply) gives, and `Start now:`.
